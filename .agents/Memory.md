# Workspace Memory

## File Naming
- Always use dashes (`-`), never underscores (`_`), for file names (kebab-case, e.g., `lighting-and-color.md`, `color-swatches.csv`).

## Visual Identity & Building Remodels
- City exterior remains 100% vanilla GTA III 2001 gritty noir.
- Storefront signs and regional billboards anchor narrative.
- Interior remodels are strictly bounded:
  - Island 1: Punk Noodles, Rosa's Apartment, Marco's Bistro, SupaSave.
  - Island 2: Staunton Ammu-Nation (shooting range), Newport Docks Warehouse (Heist Pt 1), Bedford Point Penthouse (safehouse).
  - Island 3: Pike Creek Industrial Vault (The Crown Jewel), Cedar Grove Syndicate Villa (climax), Cochrane Dam Control Room (standoff arena).
- Protagonist Rosa Chang is a retextured vanilla ped (Asuka/Maria).
- UI: Vanilla HUD; custom splash/title/loading screens.
- Lighting & Baking: `Prelit` vertex colors for broad light fills; Cycles diffuse bakes into `.txd` for complex emission/shadows. Reference: `docs/lighting-and-color.md`, `docs/color-swatches.csv`, `docs/color-swatches.html`.

## Billboard & In-Universe Ad Design
- Commercial parody ads must look authentic, clean, and professional—not like cartoonish scams.
- Avoid greasy salesman caricatures; use relatable everyday working-class customers or bold money graphics.
- High-contrast primary palettes, heavy readable sans-serif typography, and clear calls to action (e.g. phone/kiosk).
- Satire lives in the absurd terms, rates (e.g. "400% APR"), and fine-print disclaimers.

## Scripts & Utility Tooling
- All automation, diagnostic, texture unwrapping, and data scripts belong in `./scripts/` (e.g. `scripts/unwrap-billboard.py`).
- Always use kebab-case for script filenames (`script-name.py`).
- Never run inline multi-line Python scripts via `python -c`; save them to `./scripts/` and invoke the file.
- **Script Output**: Every script CLI prints through `scripts/log.ts` (`say.heading`, `info`, `done`, `skip`, `warn`, `fail`, `text`; `pass`, `error`, and `wait` for major steps). Routine lines use color only; emoji mark only compile pass or fail, waiting for the game, and final results. No `[+]` or `[-]` tag bullets.
- **Probes**: `deno task probe [name]` compiles `tests/<name>-probe.txt` (suffix and extension inferred; no name opens a picker), moves every installed `main.scm` to `<GTA3>/.main-backup/<stamp>/`, installs the probe, launches the game, waits for exit, restores the backups, and writes `tests/results/<name>-<stamp>.md` (git-ignored). A probe key named `..._expect_N` or `_expect_minusN` is checked against the value the game wrote. A probe needs `{$USE ini}` for `IniFile` commands and an `{$INCLUDE}` path relative to its own folder (`../utils/geography.txt` from `tests/`).
- **Generated Missions**: `missions/0_tutorial.txt` is generated from `missions/0_tutorial.states.ts` by `lib/fsm/generate.ts`. `lib/fsm` is the workspace package `@noodles/fsm` (root `deno.jsonc` lists it under `workspace`; import it by that name); `syncMissions` runs in `deno task build` (writes) and `deno task install` (fails on a stale file), and `scripts/sync-missions.ts [--check]` runs it alone. A table lists states with beat tables (a beat runs its steps once, then waits), a mission-level `fail` list, `monitors` with one latch local each, and `locals` (mission-private CLEO locals such as `Char sal`; `problems` counts them against the 16). A state's `on` rules are an if/else chain that ends in `until` or `next`. A state with `fail: false` (or a mission with no fail list), in a mission with no monitors, runs its beats as plain `wait`s; every other state times each beat in a `TIMERA` loop that runs the watchers. `cond.timeLimit` reads `TIMERB` (one game minute is 1000 ms; `step.startTimer` resets it), `cond.wantedAbove` reads opcode `01C0`, and `cond.carHealthBelow` reads `0227`. `missions/1_shady_job.txt` is generated from `missions/1_shady_job.fsm.json`. `LOSE` resets to `GO_HOME` and does not call `Mission.Fail()`. `finishMission()` in `utils/missions.txt` is the shared epilogue. Run `deno test -A lib/fsm` for the generator tests.
- **Mission Editor**: `tools/mission-editor` is the workspace package `@noodles/editor` (listed in the root `workspace`; same repo, not a git submodule). `server.ts` serves `ui/`; Preact with htm is vendored in `ui/vendor/preact.js` (copied from the `htm` 3.1.1 npm package), so there is no build step. `server.ts` uses inline `jsr:` specifiers: `deno desktop` failed at run time with "not a dependency and not in import map" for `@std/http/file-server` when the package's own import map supplied it, and `npm:` resolution through `import.meta.resolve` fails in a compiled binary. `deno task editor` runs `deno desktop --hmr`; `deno task --cwd tools/mission-editor serve` serves it to a browser tab (the `mission-editor` entry in `.claude/launch.json`); `deno test --allow-read` runs in the package. `ui/app.js` carries `deno-fmt-ignore-file` because the formatter breaks htm templates. Preact does not hear `onFocusOut`: Chrome has no `onfocusout` property, so Preact listens for an event named "FocusOut" that never fires; write `onfocusout` in lowercase. Preact is not runnable under Deno, so pure logic the UI needs lives in `ui/templates.js` and `ui/refactor.js` for `templates_test.ts` and `refactor_test.ts` to import. `main.ts` adopts the window with `Deno.BrowserWindow` and calls `Deno.exit(0)` on its `close` event, because `Deno.serve()` otherwise keeps the app alive after the window closes; `dev.ts` (the `dev` task) runs `deno desktop --hmr` and kills the process tree through `process-tree.ts` on exit, since orphaned `laufey_webview` and `msedgewebview2` processes locked `dist/MissionEditor` (os error 32). The close-on-window and the supervisor have not been checked in a real window; the tree kill is covered by a test. The user runs `deno task editor` in watch mode (`--hmr`) while developing, so a running `laufey_webview` whose parent is `deno desktop --hmr` is their session: do not stop it, and expect `deno task editor:build` to fail with os error 32 until they close it. Design: [`editor/mvp/README.md`](editor/mvp/README.md).
- **Geography Constants**: `utils/geography.txt` is generated from `data/geography.json` (`deno task build`); never edit it. A POI's notes (TODOs, sources, which mission uses it) go in its `comment` field and print as `//` lines above its consts. Renaming a POI field renames its consts (`PAYPHONE_NEAR_RADIUS` became `PAYPHONE_RADIUS`), and an undefined const in a hand-written script (`missions/1_shady_job.txt`, `tests/*-probe.txt`) fails with the misleading "Not enough actual parameters", so grep every `.txt` for the old name.
- **Editor Renames**: renaming a monitor or state in the Inspector rewrites `latch<Id>` and `STATE_<Id>` inside condition and step text (`tools/mission-editor/ui/refactor.js`, pure so `refactor_test.ts` can import it). `problems(mission, known)` in `lib/fsm` reports as errors: an undeclared `latch…` or `STATE_…`, a constant or `$global` that `variables.txt`, `constants.txt`, the geography file, or the mission's includes do not declare, a `$global` with no `Alloc` pin, a spot not in `data/geography.json`, a variable of the wrong declared type for its field, a `RadarSprite` member that does not exist, and an int where a float belongs (Sanny reads an int literal or constant in a float parameter as about zero). `known.ts` reads those files, and a project with no `variables.txt` skips the file-based checks. Fields come from `lib/fsm/descriptors.ts`: `spot` (POI id, written `{spot}_X`, `_Y`, `_Z`), `numeric` (`int` or `float`), `varType`, `enum`, `toggle`, `placeholder`, and `min`/`max` (a bounded `number` field renders as `input[type=number]` with those attributes); a condition's `pre` lines may hold `{field}` slots like its `lines`; the server loads `lib/fsm` once, so a running editor needs a restart before a new descriptor shows in its menus; a descriptor with `shown` flips to its partner (Add Blip and Remove Blip). `data/radar-sprites.json` is the `RadarSprite` enum from the Sanny install's `data/gta3_sbl/enums.txt` without `None`. Generated missions include `../constants.txt`. The tutorial tests read the live `missions/0_tutorial.fsm.json`, so an undeclared name added in the editor fails them until it is fixed or the mission is rebuilt.
- **Shell For Tasks**: run `deno task build`, `install`, and `probe` from PowerShell. Under the Bash tool `tar` resolves to `/usr/bin/tar` and packaging fails with "Cannot connect to C: resolve failed". `deno task probe` launches the game, so ask first.
- **Loose CLEO Scripts**: `cleo/*.txt` compile to `.cs` that go to `modloader/Noodles/cleo/` only. `install.ts` fails when `[gta3]/CLEO` holds a file of the same name, and `build.ts` drops `CLEO/*.cs` carried over from the previous zip.
- **Clean**: `deno task clean [--dry-run]` removes everything in `dist/`, compiled `data/txd/*.txd`, and `tests/results/`. Root `main.scm` and `tests/*.scm` stay.

## Texture Perspective Rectification
- When unwrapping perspective mockups (billboards, signs) into flat game textures, match Photoshop's Perspective Crop Tool.
- Identify the 4 true quadrilateral corner vertices (`TL`, `TR`, `BR`, `BL`) and map them directly using homography (`cv2.getPerspectiveTransform` and `cv2.warpPerspective`).
- Do not apply affine rotation after perspective transformation; post-warp rotation tilts the rectangular canvas and shears/clips corners.

## Mod Installation, Packaging & Game Runner
- **ModLoader Runtime Packaging**: All mod assets are packaged strictly into `dist/Drag-N-Drop.zip` under `modloader/Noodles/` (`data/main.scm`, `cleo/*.cm`, `models/gta3.img/`, `data/maps/`, `noodles_custom.txt`, `txd/`). Base ModLoader system files (`modloader/.data/`, `modloader.ini`) and video overrides (`movies/GTAtitles.mpg`) reside at the archive root.
- **Installer Cleanup**: `scripts/install.ts` removes `[gta3]/modloader/Noodles` before unpacking `dist/Drag-N-Drop.zip` to prevent unmanifested or disabled assets from persisting in the game.
- **Model Manifest Discipline**: `models/manifest.csv` (`name,folder,dff,txd,col,col_level,enabled`) controls which models are compiled and packaged into `models/gta3.img/`.
- **Build Pipeline Model Compilation**: `scripts/build.ts` Step 3 automatically compiles `.blend` models for enabled manifest entries via `scripts/export-blend-models.py` and patches the internal 22-byte COLL model header to match `entry.name`.
- **Map & Collision Injection**:
  - In GTA III, custom map object collisions must NOT be placed in `models/gta3.img` (causes streaming install/uninstall conflicts); they belong in `data/maps/noodles/col/` registered via `COLFILE <level>` in `data/noodles_custom.txt`; `build.ts` step 4 writes the level from the manifest `col_level` column.
  - The internal COLL model name in the 22-byte archive header must strictly match the IDE model name (e.g. `rosa_apartment`, not `rosa_apartment.col`).
  - `build.ts` automatically synchronizes `data/noodles_custom.txt` against `models/manifest.csv`, commenting out disabled collision files before packaging.
  - Any model instantiated in `custom.ipl` must be declared in `custom.ide` and present in `gta3.img`, otherwise the engine dereferences a null `pColModel` at `0x0047402D`.
  - `data/maps/noodles/col/*.col` are git symlinks (mode `120000`) to the COL artifacts under `models/<folder>/`; `build.ts` step 4 copies with `copyFollowingSymlinks` so the zip holds real files.
  - Manifest `name` is the IDE model name. `dff` and `col` are the source file names inside the model folder (the exporter writes `<collection>.dff`, e.g. `rosa_apartment.dff`); `build.ts` stages them as `<name>.dff` and `<name>.col` (e.g. `ind_newtenement08.dff`), and `noodles_custom.txt` `COLFILE` lines use `<name>.col`. The stock COL archive entry for `ind_newtenement08` is in `data/maps/industne/INDUSTNE.col`.
  - `build.ts` step 4 writes each manifest folder's `*.pos` (`x y z`) into the matching `custom.ipl` `inst` line (matched by the `dff` basename). Without a `*.pos`, `custom.ipl` stays the source of truth. `custom.ide` has no coordinates and is never synced.
  - Stock `ind_newtenement08` is ID `445` (`industne.ide`: `445, ind_newtenement08, inditaly1, 1, 115, 0`), already placed by `industNE.ipl` at `1160.77, -407.514, 33.3118`. An override in `custom.ide` reuses `445`; a new ID such as `3895` has no stock definition.
  - `col_level`: `ind_newtenement08` loads at `0`; `dinerind` loads at `1` (its stock entry is in `models/coll/indust.col`). `dinerind.col` at level `0` crashed at `0x00411643` with `ESI=0x16C` and `EBP=13` (13 stock boxes × 28 bytes); level `1` did not crash.
  - Collision triangles are one-sided. Run `python scripts/check-col-normals.py <file.col>`: stock and working COL floors report `facing DOWN` (z-normal sign of `(b-a)x(c-a)`); a floor reporting `UP` is wound opposite and the player falls through it. DragonFF flips winding on export, so a floor polygon needs a `+Z` normal in Blender (the in-game result of flipping is not yet recorded). `python scripts/inspect-blend-col.py <blend>` lists each COL object's modifiers and horizontal polygon counts as stored and as evaluated.
  - Blender edits reach a COL or DFF only after the `.blend` is saved and `deno task build` runs; the build skips export when the saved file's hash is unchanged.
  - `deno task install` reruns `build` without flags; for a flagged build (`--skip-asset=...`), run `deno task build --skip-asset=...`, then `scripts/install.ts` directly.
- **Build Incrementality**: `scripts/build.ts` skips unchanged work via SHA-256 hashes in `dist/.build-cache.json`: step 1 and 2 hash each script plus its `{$INCLUDE}` files (a mission also hashes `main.txt`, so a mission rebuilds when main's includes change); step 3 hashes each `.blend`. Outputs must still exist for a skip.
- **Sanny CLI Race**: `sanny.exe --compile` can return before the output file exists, so the first `deno task build` after a source change can fail copying the `.cm` to staging. Rerun the build.
- **Install Conflict Lint**: `scripts/install.ts` exits `1` and lists any file in `[gta3]/CLEO` (and `CLEO/CLEO_TEXT`) that duplicates a packaged `modloader/Noodles/cleo` file. CLEO loads that folder directly, so a stale copy there shadows the modloader one.
- **Build Shell**: Run `deno task build` from PowerShell. Git Bash's GNU `tar` fails the zip step with "Cannot connect to C: resolve failed"; Windows `tar` works.
- **Frontend TXDs Location**: Frontend and boot textures reside in `data/txd/` (moved from legacy `assets/`) and package into `modloader/Noodles/txd/`.
- **Step Bisection**: `scripts/build.ts` supports interactive bisection and filtering via `--bisect`, `--step=<N>`, `--only=<name>`, and `--skip=<name>`.
- **UAC Bypass Runner**: When Windows sets `WINXPSP3` on `gta3.exe` in HKLM, launching directly throws OS error 740. Hardlink runner `gta3-game.exe` bypasses the exact-path registry flag with zero UAC prompts via `deno task run`.

## CLEO III Mission Scripting
- **Global Slots**: Sanny gives each script's undeclared `$globals` slots in first-use order from index `4313`, and `var` blocks do not allocate. Every global shared by main, `utils/`, or several scripts is pinned with `Alloc($name, index)` in `variables.txt` (shared 4400 to 4410 with `$onMission` at 4409 and `$skipCutscene` at 4410, main 4501 to 4512 with `$VanBlip` at 4504), included first by `globals.txt` and each mission. Mission-private state is a CLEO local (`int x`, `Char sal`) declared at the top of its mission, not a global. Never reuse an index (two names on one index share one cell). `scripts/lint-scripts.ts` runs in `deno task build` and `deno task install` and fails on duplicate pins, slots outside `$2` to `$3FFF`, an unpinned `$global` in a mission, or more than 16 locals in a mission. See [`reports/bugs/mission-global-slot-mismatch.md`](reports/bugs/mission-global-slot-mismatch.md).
- **Functions**: Arguments are numbers only: CLEO III's `0AB1` reads them with the game's numeric parameter reader (`III.VC.CLEO` `CustomOpcodes.cpp`, `CALL_SCM_FUNCTION`), so strings cannot be passed. `cleo_return` takes the value count first (`cleo_return 1 value`). Three-operand float sums compile to `INT_ADD`; write `float x = a` then `x += b`. See [`reports/bugs/cleo-return-count-crash.md`](reports/bugs/cleo-return-count-crash.md).
- **CLEO Locals**: `int x = 1` declarations compile only after `{$CLEO}` (or `{$CLEO .cm}`); under `{$USE CLEO}` with `{$EXTERNAL}` they fail with "Unknown directive". A script gets 16 locals; the 17th fails with "Not enough memory to allocate a local variable". Locals inside a `function` do not count against the script's 16, but a `function` cannot see the script's locals (its body fails with "Unknown directive"), so a routine that reads or writes mission state is a label subroutine (`:name` ending in `return`, called as `name()`). `Char sal` or `var sal: Char` compiles as a local. Errors are written to `compile.log` in the Sanny folder, and the CLI exits 0 and still writes an output file; `scripts/build.ts` now fails on a new log entry naming the input, `deno task build --force` ignores the hash cache, and `scripts/check-compile.ts <script.txt>` compiles one script to `dist/.lint/out` and prints its log entry. See [`reports/bugs/sanny-compile-errors-hidden.md`](reports/bugs/sanny-compile-errors-hidden.md). `scripts/test-sanny-locals.ts` reproduces all of this (`deno run --allow-all --env-file=.env scripts/test-sanny-locals.ts`). Compile-only: nothing was run in the game.
- **Gosub Depth**: A script keeps six `gosub` return addresses (`m_aGosubAddr[6]` in `plugins/sockets/III.CLEO.h`). [`tests/stack-probe.txt`](../tests/stack-probe.txt) on `main.scm` entered seven nested `gosub`s and crashed on the eighth, so the seventh overran into the next field; six is the safe depth. A `return` inside a `while` inside a `gosub` works. A `.cm` thread is untested. The FSM generator nests at most two deep plus what a step calls. See [`reports/rejected-fsm-codegen-options.md`](reports/rejected-fsm-codegen-options.md).
- **FSM Codegen**: `lib/fsm/generate.ts` emits a dispatcher loop and one `:state<Id>` label routine per state, each with its own tick loop that ends in `return`; `failCheck`, `leave<State>`, and `runMonitors` are shared routines, and beats wait in `TIMERA` loops only in states a monitor or the fail check watches. Design and rejected alternatives: [`reports/fsm-codegen-patterns.md`](reports/fsm-codegen-patterns.md) and [`reports/rejected-fsm-codegen-options.md`](reports/rejected-fsm-codegen-options.md). The build recompiles a script only when it or a file it includes changes (`scripts/includes.ts`).
- **Debug Tools**: `utils/debug.txt` (`debugLogInt`, `debugLogFloat`, `debugLogHeading`, `debugCount`, `debugTrace`) streams readings over UDP to `127.0.0.1:TELEMETRY_PORT` (8089) through `sockets.cleo` opcode `0B31`, so no INI is written and a frame costs a compare. Callers pass a `DEBUG_*` channel constant from `constants.txt`; adding a log point is one const. The plugin sends a reading only when it changes (or once a second), counts `debugCount` calls itself, and sends every `debugTrace` step. Packets are `DBG:<channel>,<i|f|c|t>,<value>`. `utils/cars.txt` logs the `$myCar` readings each frame while `$myCar > 0`. `deno task run` binds UDP 8089 while the game runs, writes every reading and capture (plus one position a second) to `dist/telemetry/run-<stamp>.jsonl`, and prints a per-channel summary and the last 12 events after the game exits; it skips the capture with a warning when the mission editor already holds the port (`scripts/telemetry.ts`, tested by `scripts/telemetry.test.ts` with `--allow-net=127.0.0.1 --allow-read --allow-write`). The editor's Run button posts `/api/run`, which starts `deno task run --events` and relays its `@telemetry` event lines (`scripts/run-events.ts`) as SSE events to the debugger pane's Game Run and Script Watches sections; the server lets go of UDP 8089 for the run. The crash verdict comes from the game's logs, not the exit code (`scripts/game-exit.ts`: a normal quit exits with an arbitrary code because WinMain returns the last window message's wParam). The editor's `Deno.listenDatagram` needs `--unstable-net` on Deno 2.9, so its `catch` hides a failed bind; `node:dgram` works without a flag. The old INI route is gone, so `debug_ini` in the game-logtail MCP no longer receives readings.
- **Main-Loop Car Checks**: `utils/cars.txt` runs inside the main loop and calls car natives (`Car.IsInWater`, `Car.IsUpsidedown`, `Player.IsInCar`) only inside `if $myCar > 0`, so no native receives handle 0. It declares no `var` block: a `var` in an included main-loop file declares an unpinned global, and `variables.txt` owns every global slot. `Car.MarkAsNoLongerNeeded` runs before `$myCar = 0`.
- **Geography Constants**: `utils/geography.txt` holds every coordinate that `main.txt` and `missions/` use, named `<PLACE>_<WHAT>_<AXIS>` (for example `NOODLES_X`, `SAFEHOUSE_CAM_Z`). `main.txt` and each mission include it right after `variables.txt`. Add a new location there and reference it by name; do not write coordinate literals in scripts. `utils/pickups.txt`, `utils/spawn_points.txt`, `utils/packages.txt`, and `utils/functions.txt` keep their own literals.
- **INI Plugin**: The `0AF0`-`0AF5` ini opcodes need `CLEO\CLEO_PLUGINS\III.IniFiles.cleo` from the official `cleolibrary/III.VC.CLEO` release matching the installed core (2.1.1). The `IniFiles.cleo` already in that folder is a CLEO Redux plugin and does not register them for CLEO 2 (the game shows "Incorrect opcode ID: 0AF3"). Use a path with a folder (`CLEO\debug.ini`): a bare file name makes Win32 use the Windows directory, where a non-admin write fails silently.
- **Main Loop Versus Missions**: `main.txt` runs every frame while a mission thread runs. Its camera-avoidance block checks `$onMission == false` in its `if and`, and its `else` branch (`Camera.Restore()`) is nested in a second `$onMission == false` check; a per-frame block that touches the camera or the player's heading must stay inside that guard. See [`reports/bugs/mission-facing-camera-interference.md`](reports/bugs/mission-facing-camera-interference.md).
- **SCRLog**: The game's `scrlog.log` kept only the last frames before exit in this setup (the cutscene was missing), so it cannot capture a mid-session event. The game's `scrlog.ini` currently has `FLUSH_TIME=FLUSH_ON_WRITE`. Its last frames still show which commands ran per frame, which found the repeated-removal crash.
- **One-Shot Entity Removal**: Calling `Char.RemoveElegantly` on the same handle every frame crashes the game. Guard removal so it runs once. See [`reports/bugs/repeated-remove-elegantly-crash.md`](reports/bugs/repeated-remove-elegantly-crash.md).
- **Missing Includes**: An `{$INCLUDE}` path that resolves to no file is skipped without an error, so its constants are undefined and a later line fails with a misleading message (e.g. "Not enough actual parameters"). Write include paths relative to the script's own folder.
- **Blips and Spheres**: `Blip.AddSpriteForContactPoint` (`02A7`) is documented as hidden while on mission, and `Blip.ChangeDisplay(..., BlipDisplay.Both)` did not make it appear in a user test during mission 1. It also draws its own world sphere (Sanny: "blip and sphere"), which showed as a second sphere beside the locate sphere at Punk Noodles; `main.txt` adds that blip with `Blip.AddSpriteForCoord`, which has no sphere, and removes it when mission 1 starts. The payphone blip uses `Blip.AddSpriteForCoord` too. ## Game Log Monitoring (MCP)

## Blender Model & Collision Export Architecture
- **Root Collection Naming**: Root collections named `*.dff` and `*.col` in `.blend` files define the output models.
- **Single Atomic DFF Export**: `scripts/export-blend-models.py` merges all render-enabled subitems (`hide_render == False`) into a singular unified atomic mesh with world transformations applied and root frame origin at `(0, 0, 0)`.
- **COL Export Full Scope**: For `*.col` collections, all mesh elements are exported normally (`obj.dff.type = 'COL'`, collision v1), ignoring Blender visibility flags.
- **Export Script**: Automated via `python scripts/export-blend-models.py <blend-file> [out-dir]`.
- **No World Position Compensation**: Never shift IPL or world map placement coordinates (`custom.ipl`, `.pos`) to compensate for local frame offset or unapplied mesh transforms. Model origins and root frame hierarchies must be fixed in the model itself.

## RenderWare GTA III Compatibility Constraints
- **Pipeline Plugin (`0x253F2F3`)**: In DragonFF, `obj.dff.pipeline` must be set to `NONE`. Never export with GTA SA building pipeline (`0x53F20098`), which causes GTA III to fail to bind render pipelines.
- **Night Vertex Colors (`0x253F2F9`)**: Must be disabled (`night_cols = False`). GTA III does not support SA night vertex colors plugin.
- **Collision Plugin (`0x253F2FA`)**: Must not be embedded in DFF (`export_coll = False`). GTA III map objects require external `.col` files.
- **Version**: Export version must strictly target GTA III PC `0x32000` (RenderWare v3.2.0.0 / library ID `0x0800FFFF`), matching all vanilla GTA III models. Do NOT use `0x33002`; DragonFF writes a 12-byte clump struct `(num_atomics, num_lights, num_cameras)` for versions `>= 0x33000`, whereas GTA III PC expects the 4-byte clump struct `(num_atomics)` emitted when version is `< 0x33000` (`0x32000`).
- **Texture Dictionary Platform**: A model's `.txd` must be Direct3D 8 (platform `8`, device `0`, stamp `0x320`). A Direct3D 9 TXD imports without error but leaves its models invisible; convert it with `scripts/convert-txd-d3d9-to-d3d8.py <in.txd> <out.txd>`. See [`reports/bugs/rosa-tenament-invisible.md`](reports/bugs/rosa-tenament-invisible.md).
- **Inspection Tooling**: Use `scripts/inspect-dff.py <model.dff>` to inspect RW version, clump frame hierarchy, geometry vertex/triangle bounds, prelit alpha ranges, texture references, and atomic flags.
- **DragonFF Material Mapping**: Image texture nodes must have clean `node.label` values matching texture names to prevent DragonFF's `clear_extension` from truncating `.txd` prefixes into model texture names. Sampler properties must be set to `tex_filters = 6` (Linear Mipmap Linear) and `tex_u_addr = tex_v_addr = 1` (Wrap).

## Mission Editor
- **Plans**: [`editor/mvp/README.md`](editor/mvp/README.md) and [`plans/debugger-pane.md`](plans/debugger-pane.md).
- **Inspector Form**: The Script pane edits the selected state, or the mission when nothing is selected; beats belong to the Beat pane. State kinds (`cutscene`, `tutorial`, `objective`, `interaction`, `encounter`, `choice`, `ending`) choose default sections only (`ui/sections.js`). Not built, each waiting on generator support: Spawns, Reward (an amount that generates the pass tune, `register_mission_passed`, score, and banner), Time Limit (a mission timer over a state range with one local, and a per-state limit counted from entering that state), Control (player control on or off), Prompt, and a state-level Spot section. Open questions: whether `kind` shows in the graph as a card color or icon, and where Spawns positions come from (the geography catalog's Spot typeahead covers step cards).
- **Modes & Layout**: App header provides `[Edit | Debug]` toggle. `Edit` displays the `Script` pane; `Debug` displays the `Debugger` pane (Player HUD with a copy button, Game Run, Watches, Captures, and disabled Pause / Resume and Step buttons in its heading) and enables the header telemetry pill, the only place connection status shows. Redundant sidebar tabs are eliminated. Undo and Redo are one segmented icon group. The States and Assets panes in the left sidebar have a splitter, and all four pane sizes (`left`, `right`, `timeline`, `states`) persist under `mission-editor.pane-sizes` in `localStorage`.
- **Telemetry & Captures**: `cleo/capture.txt` is meant to broadcast 15Hz player telemetry and F8 captures over UDP port 8089, but the game never runs it (open: [`bugs/player-telemetry-debug.md`](bugs/player-telemetry-debug.md)). A standalone CLEO script must `{$INCLUDE ../variables.txt}` to read main's `$player` slot and be started by `main.txt` (`scripts/lint-scripts.ts` enforces both); check `cleo.log` in the game folder for `Loaded script` or `Error(script loading)`. `tools/mission-editor/server.ts` relays UDP packets via SSE at `/api/telemetry` to `DebuggerPane` and `AssetsPane`. The SSE `Response` must carry its own `Content-Type: text/event-stream`, because `c.header` is lost when a handler returns its own `Response` and a browser's `EventSource` then aborts.
- **Run in Game**: The header Run button posts `/api/run` (disabled while blocking problems exist), which starts `deno task run --events`; while the game runs it becomes a red Stop button that posts `/api/stop` and ends the run's whole process tree. The editor needs `--allow-run=deno,powershell,pkill` (set in the `deno.json` tasks and `dev.ts`): `deno` starts the run, and `process-tree.ts` uses `powershell` (or `pkill` elsewhere) to end the tree; without `deno` the run answers a 500 and without `powershell` Stop throws. `process-tree_test.ts` runs `fixtures/kill-tree.ts` under each start path's flags. The server has no hot reload, so server and flag edits need an editor restart. A run resets the server's readings and sends a fresh `status` event; the game counts as connected from the run's `launch` event until it exits (readings arrive only on change); run output reaches the log with ANSI codes stripped. `run-integration_test.ts` drives these through a real child process (`fixtures/fake-run.ts`), UDP, and SSE.
- **Data**: a `.fsm.json` wins over a `.states.ts`; the editor writes one on a mission's first edit. `syncMissions` (so `deno task build`) generates the `.txt` from whichever table the mission has, the `.fsm.json` first.
- **Checking the UI**: serve `createApp` on a spare port (not 8000, which may be the user's) against a throwaway project seeded by a `PUT`, never the repo's `missions/`. Run tests with `deno task --cwd tools/mission-editor test`, which grants `--allow-run`.
