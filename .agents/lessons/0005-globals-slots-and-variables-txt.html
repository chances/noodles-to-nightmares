Globals, Slots, and Variables

Mission: stop globals from landing on the wrong slot between main.scm and the .cm missions. Target: GTA III, Sanny Builder mode gta3_sbl. Covers every open question about variables.

1. What a Global Is

A global is a named cell in one global variable space that every script on the running game shares. When Sanny compiles, each $name gets a numeric index in that space, and the runtime reads and writes by index. Names do not exist at runtime. A name that is already numeric, such as $100, keeps its index. A name such as $var gets whichever index is available during that compile (Sanny docs: Variables).

main.scm and each .cm are separate compiles. Two compiles that both write $sal can pick different indices, and both then write into one shared space. That is the whole reason variables.txt exists.

The repo's own record of this failure is mission-global-slot-mismatch.md: $sal landed on the slot of $isCameraAvoidingObstacle, which main rewrote every frame, and the engine dereferenced a bad ped handle.

Per the docs, Alloc takes a global variable and a non-negative integer (error 0079 otherwise). The slot's byte offset in main.scm is the index times four (docs: $40 sits at offset 160), so $4404 is offset 17616 (0x44D0). Valid names run $2 to $3FFF (error 0088), and GTA III allows 16381 globals in total.

4. ❓ Why Can't Mission Allocations Live in the Missions?

This was the question on variables.txt line 53. They can, if the variable stops being a $global, and they now do. A $name in a .cm is a slot in the shared space, so a private $thief still gets an index that only that compile chose, and nothing ties it to the slots main uses. A CLEO local has no slot in that space at all. Per the docs, a local is available only within its own script, and the int a = 1 syntax works in CLEO scripts only. GTA III allows 16 locals plus two timers per script (GTA Limits).

// Before: a pin in variables.txt, shared by every compile
Alloc($isDriving, 4515)
$isDriving = false

// After: a local, declared at the top of 0_tutorial.txt only
int isDriving = false

A function has its own locals, so it cannot see the mission's. checkSafety and tryRemoveSal read and wrote mission state, so they became label subroutines (:checkSafety ending in return, still called as checkSafety()), which share the script's locals.

The busiest mission, the supply run, declares 11 of its 16 locals. scripts/test-sanny-locals.ts compiles small {$CLEO} scripts with the Sanny CLI in mode gta3_sbl and reads compile.log:

The compiler accepts int x = 1 only after {$CLEO} (or a variant such as {$CLEO .cm}). Under {$USE CLEO} with {$EXTERNAL} the same line fails with "Unknown directive".

5. The Lint and the Mission Flag

A name in no Alloc line gets a slot from its own compile's first-use order, the condition behind the $sal crash. scripts/lint-scripts.ts now runs at the start of deno task build and deno task install and fails on:

RuleWhy
Two names on one slot, or one name on two slotsTwo names would share one cell
A slot outside $2 to $3FFFSanny error 0088
A $global in a mission with no Alloc pinIts slot comes from that mission's own first-use order
More than 16 locals in a mission (outside function bodies)GTA III allows 16 locals per script

The build also reads compile.log after every Sanny compile, because the CLI exits 0 on a compile error and still writes an output file (sanny-compile-errors-hidden.md). deno task build --force ignores the hash cache and recompiles everything.

$onMission is pinned at 4409 so main and every mission share one cell. Main declares it with declare_mission_flag in globals.txt line 6, after the include of variables.txt. The engine accepts a pinned variable there.
