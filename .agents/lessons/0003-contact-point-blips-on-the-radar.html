Contact Point Blips on the Radar

Mission: show the payphone on the minimap while Rosa is on mission 1. Targets missions/1_shady_job.txt line 103.

1. Why the Radar Shows Nothing

The library describes Blip.AddSpriteForContactPoint (opcode 02A7) as adding "a long range sprite blip and sphere to the contact point that is not displayed while on mission" (02A7). A mission sets $onMission = true, so this blip type stays hidden for the whole mission. The library does not describe Blip.AddSpriteForCoord (02A8) as hidden on mission.

The contact point blip draws its own sphere, separate from the drawSphere flag on locate commands.

4. Two Ways to Mark the Payphone

Option A: Keep the Contact Point

This keeps the contact point blip and its sphere. The blip stays hidden while on mission, and Blip.ChangeDisplay is not documented as overriding that.

Blip.AddSpriteForContactPoint(1168.33, -414.841, 22.8, PAYPHONE, $payphoneBlip)
Blip.ChangeDisplay($payphoneBlip, BlipDisplay.Both)

Option B: Use a Plain Coordinate Blip

This uses the command behind $SafeBlip in main.txt. The library does not describe it as hidden on mission:

$payphoneBlip = Blip.AddSpriteForCoord(1168.33, -414.841, 22.8, PAYPHONE)

5. The Blip Pool Has a Limit

Every blip occupies one slot in a fixed pool. The GTA Limits table lists the radar blip capacity per game:

GameRadar Blips
GTA III32
Vice City75
San Andreas175
San Andreas Mobile250

An add command that creates a blip each frame, or overwrites its handle variable without calling Blip.Remove, fills the pool. This project logged -1 handles from every add command while the pool was full (blip-pool-exhausted-by-safehouse-blip.md).

When a blip is missing, log the handle the add command returns before changing any display settings. A handle of -1 means no blip exists.
