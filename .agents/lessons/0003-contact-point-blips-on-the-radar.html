Contact Point Blips on the Radar

Mission: show the payphone on the minimap while Rosa is on mission 1. Targets missions/1_shady_job.txt line 103.

1. Why the Radar Shows Nothing

The library describes Blip.AddSpriteForContactPoint (opcode 02A7) as adding "a long range sprite blip and sphere to the contact point that is not displayed while on mission" (02A7). The mission script sets $onMission = true, so the library text predicted this blip stays hidden. That prediction was not the cause here: the van, payphone, and pickup blips were all missing, and none of them is a contact point blip. Section 5 shows the real cause.

The blip carries its own sphere, so the orb is not only the draw flag on the locate check.

4. Two Candidate Edits

Option A: Force the Radar Icon On

This keeps the contact point. Tested in game: no blip appears on the minimap, even beside the payphone.

Blip.AddSpriteForContactPoint(1168.33, -414.841, 22.8, PAYPHONE, $payphoneBlip)
Blip.ChangeDisplay($payphoneBlip, BlipDisplay.Both)

Option B: Use a Plain Coordinate Blip

This uses the command behind $SafeBlip in main.txt. The library does not describe it as hidden on mission:

$payphoneBlip = Blip.AddSpriteForCoord(1168.33, -414.841, 22.8, PAYPHONE)
018B does not override the hiding, so Option A fails. Option B is in the mission now and also showed nothing, so the cause is not the contact point command. Section 5 explains why.

5. The Real Cause: a Full Blip Pool

The mission logged each blip handle to CLEO\debug.ini right after the call that created it:

KeyValueMeaning
Van, Payphone, Pickup-1The blip call failed
VanHandle11010The car existed
PlayerHandle0The mission read the right global slot

Every Blip.Add* command returns -1 when the blip pool has no free slot. main.txt called ensureSafehouseBlip() on every frame off mission, and each call added another blip and overwrote $SafeBlip, so the old handles leaked. The fix is a $SafeBlip == 0 guard. Details: .agents/reports/bugs/blip-pool-exhausted-by-safehouse-blip.md.

When a blip is missing, log the handle the add command returns before changing any display settings.
